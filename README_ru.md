# Browser Agent · 1.0.0

[English version](README.md)

ИИ-ассистент для Chromium-браузеров: чат, поиск, управление вкладками и инструменты Chrome DevTools Protocol. Основные целевые браузеры — Chrome/Chromium и Яндекс.Браузер.

Версия отображается в «Настройки → Интерфейс» и «Диагностика».

## Установка и сборка

Нужен Node.js 22.12+ в ветке 22, Node.js 24 или Node.js 26+.

```sh
npm ci
npm run build
```

На странице `chrome://extensions/` или `browser://extensions/` включите режим разработчика и загрузите папку `dist` как распакованное расширение. После пересборки обновите расширение и открытые веб-страницы.

Открытие: кнопка расширения, Alt+C, контекстное меню или перетаскиваемая кнопка Agent на странице. Если sidePanel недоступна, интерфейс открывается во вкладке расширения. Горячая клавиша настраивается средствами браузера.

Плавающая кнопка — круглый значок чата, совпадающий с логотипом расширения. При перетаскивании появляется круглая зона «Закрыть»: сброс в неё скрывает кнопку в этой вкладке. Её можно вернуть, выключив и снова включив виджет в настройках. Положение запоминается. PNG-иконки для панели браузера генерируются из `public/icons/logo.svg` командой `npm run icons` (нужен тестовый Chromium).

## Настройка

- **Модели:** RouterAI, AItunnel, OpenAI, DeepSeek, Gemini, Anthropic, Custom/OpenAI-compatible. У каждого провайдера сохраняется отдельный ключ и модель. Для локальных OpenAI-compatible серверов ключ необязателен.
- **Инструменты:** DuckDuckGo или Tavily, каталог из 29 инструментов, поиск, переключатели и подробная справка. Изменения применяются после сохранения; отключение проверяется исполнителем.
- **Контекст и история:** реальный лимит выбранной модели, резерв ответа, порог сжатия и профиль вывода.
- **Поведение:** дополнительные инструкции, температура, лимит шагов и автоматическое подключение CDP.
- **Интерфейс:** тема, язык, плавающая кнопка, звук завершения и громкость.
- **Диагностика:** наличие API браузера, объём артефактов, очистка и экспорт конфигурационной диагностики без ключей.

В «Модели» есть явная проверка подключения. Это небольшой платный API-запрос по тарифу провайдера. Наличие модели в списке само по себе не подтверждает поддержку tools или vision. Изображения включаются отдельным переключателем для совместимой модели.

Если язык не выбран, он определяется автоматически по языку интерфейса браузера с запасным вариантом через `navigator.languages`. Ручной выбор русского или английского имеет приоритет.

## История и контекст

Полная переписка хранится отдельно от контекста, отправляемого модели. `/compact` добавляет отметку о сжатии и обновляет сводку; сообщения остаются видимыми. Повторное сжатие учитывает предыдущую сводку. Откат к более раннему сообщению сбрасывает несовместимую сводку.

Шаги одной задачи собраны в один ответ ассистента с раскрываемым «Сводом действий». В счётчике истории и пороге сжатия это одна реплика, а не отдельное сообщение на каждый инструмент. Итоговая строка usage суммирует все API-запросы этого ответа; текущий контекст показывается отдельно в индикаторе.

Перед каждым запросом учитываются инструкции, схемы инструментов, история, изображения и резерв вывода. Сжатие выполняется заранее, на границе завершённых ходов. Порог числа сообщений — повод для сжатия, а не молчаливого удаления сообщений. Если текущий неделимый ход не помещается даже после сжатия, агент явно сообщает об этом, сохранив историю.

Индикатор показывает оценку следующего запроса с разбивкой. Фактический usage API, если доступен, отображается у ответа. Оценки не являются точным токенизатором всех моделей.

Большие результаты, JSON, HAR и скриншоты хранятся в IndexedDB как артефакты. В текстовый контекст попадает ограниченная проекция, метаданные и `artifactId`. Изображения передаются в vision отдельным каналом только по запросу инструмента и при включённой поддержке модели. Ранее полученное изображение можно повторно приложить через `artifact_read` с `vision:true`.

Известные поля паролей, API-ключей, auth-заголовков и токенов скрываются в текстовых результатах и JSON-артефактах. Ключи провайдеров хранятся отдельно от переписки. Доступ к артефакту и истории проверяется по текущему диалогу.

### Контракт результата инструмента

```json
{
  "ok": true,
  "summary": "Action completed",
  "data": {},
  "truncated": true,
  "truncation": ["Array: 25 of 300 items"],
  "artifact": { "id": "...", "mime": "application/json", "bytes": 12000 },
  "next": "artifact_read ...",
  "tokens_est": 250,
  "profile": "balanced"
}
```

Лимит проверяется после сериализации всего конверта, включая метаданные и экранирование.

| Профиль | Максимум символов конверта | Элементы коллекции | Строка | Глубина |
|---|---:|---:|---:|---:|
| Lean | 2400 | 10 | 300 | 3 |
| Balanced | 7200 | 25 | 700 | 4 |
| Full | 18000 | 100 | 4000 | 8 |

`full:true` сохраняет исходный захваченный результат в артефакт; он не снимает лимит текста запроса. Собственные ограничения захвата CDP/DOM/JS и пропуски кольцевого буфера сообщаются отдельно. Для дальнейшего чтения доступны `limit`, `cursor`, фильтры, JSON-путь и `artifact_read`. `history_read` позволяет добрать ранние сообщения текущего чата после сжатия.

Артефакт: до 8 МиБ. Общее хранилище артефактов: до 64 МиБ, срок хранения 7 дней; старые файлы удаляются первыми. Вложения vision: до двух изображений, до 2 МиБ каждое на один запрос. История сообщений не удаляется при очистке артефактов. При истечении срока файл явно отмечается как недоступный.

## Инструменты

- Страница: основной текст, компактный DOM с элементными ссылками, Accessibility.
- Действия: клик, ввод, наведение, select/checkbox/radio, клавиатура, прокрутка, ожидание.
- Вкладки: список, создание, выбор, закрытие, обновление, назад/вперёд.
- DevTools: JavaScript, Console, Network, тела запросов/ответов, DOM/CSS, Storage/Cookies, Performance/Profiler, эмуляция, Debugger, CDP-команды и журнал событий.
- Поиск: DuckDuckGo по умолчанию, Tavily с отдельным ключом; чтение публичной ссылки без навигации вкладки.
- Данные: артефакты, история текущего диалога, подробная справка инструментов.

Network по умолчанию возвращает агрегат. `mode:"list"` включает выборки, `mode:"har"` создаёт скачиваемый HAR с сохранёнными метаданными. Тела получаются отдельно через `devtools_network_detail`. HAR содержит сведения о покрытии; ранее не наблюдавшиеся запросы и не захваченные тела не восстанавливаются.

Каждый запуск привязан к чату и целевой вкладке. Обычное переключение вкладки пользователем не перенаправляет выполняемую задачу. Инструмент выбора/создания вкладки меняет цель явно. При смене чата запрос отменяется, а поздний ответ не изменяет новый диалог. При лимите шагов выполняется запрос итогового ответа без инструментов. Пустой итог обрабатывается повторным завершающим запросом либо понятным локальным сообщением об ошибке.

## Границы браузерных API

`chrome.debugger` поддерживает [ограниченный браузером набор CDP-доменов](https://developer.chrome.com/docs/extensions/reference/api/debugger). `devtools_cdp` оставляет доступ к низкоуровневым командам этих доменов. Некоторые команды и flat child sessions зависят от версии Chromium. Для frame-local hover/сложных межпроцессных кадров используются явные дочерние CDP-сессии. Ссылки на DOM-элементы действуют только в своём документе/frame и становятся недействительными после навигации.

Console/Network начинают наблюдение при подключении debugger; буферы конечны. Открытие штатного DevTools может отключить debugger расширения. Уже отправленная браузеру команда может завершиться после остановки запроса; такие действия автоматически не повторяются.

Адаптивный интерфейс проверяется на ширинах 320, 360, 390 и 480 px. Возможность установки расширения и доступность sidePanel/debugger на реальном мобильном устройстве определяются его браузером.

DuckDuckGo может блокировать программные запросы. Блокировка/CAPTCHA сообщается как ошибка, а не как «результатов нет»; доступен Tavily. `web_read` получает публичный HTML/текст без cookies. Для авторизованных или JS-rendered страниц предназначены браузерные инструменты.

## Проверки

```sh
npm run typecheck
npm test
npx playwright install chromium
npm run test:e2e
```

Для размещения тестового браузера во временной папке задайте `PLAYWRIGHT_BROWSERS_PATH`. Браузерные тесты используют чистый временный профиль, собранную папку `dist`, локальные тестовые страницы и подменённые ответы LLM; реальные ключи не нужны.

Автоматический запуск распакованного расширения в установленном Яндекс.Браузере 26.8 блокировался с `ERR_BLOCKED_BY_CLIENT`. Браузерный прогон выполнен в Chromium; Яндекс требует отдельной проверки после обычной ручной установки `dist` через интерфейс расширений.

Проверяются бюджеты, сериализация, агрегация, пагинация, артефакты, изоляция сессий, миграция, сжатие, остановка, финализация и протоколы всех семи провайдеров. Браузерные сценарии проверяют адаптивность, выбор моделей, сохранение переписки, реальный CDP, HAR и скриншоты. Живая проверка провайдера выполняется отдельно кнопкой подключения с собственным ключом.

```text
src/services/artifacts.ts       IndexedDB, артефакты и лимиты

tests/unit/                    Регрессионные тесты
tests/e2e/                     Браузерные сценарии
```
